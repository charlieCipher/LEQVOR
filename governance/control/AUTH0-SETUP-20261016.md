## Signed roles and live revocation

Existing `access-registry.mjs` is the fail-closed consumer. New
`access-decisions.mjs` implements the producer core for a **separately operated**
service; it is not imported into the control runtime and has no public listener.
It requires explicit independent directory and signing adapters, with no local
private-key/default-directory fallback.

The producer authenticates the scoped reader using a constant-time hash check,
requires the exact tenant/subject/jti/token-expiry binding and a fresh 32-byte
nonce, then atomically queries the authoritative role and revocation record. It
signs only a supported assigned role, with a 30-second decision lifetime capped
by token expiry. It rechecks the binding/revision after signing and verifies the
returned signature and exact payload using the independent public key pin.
Revocation, role changes, signer substitution, directory outage or slow signing
cause denial. No cached successful decision or JWT role grants access.

Six producer acceptance tests include real signed interoperability with the
existing consumer: role changes take effect on the next lookup, and revocation
denies the next lookup without waiting for the access token to expire. Tests use
disposable software signing fixtures; no production issuer key or session grant
was created. The production signing key must be distinct from all founder keys
and retained by the independent signing operator, not Render control code.

**Not yet live:** a protected authoritative session/role store, its issuance and
revocation administration, an independently controlled signer, authenticated
hosting and transport acceptance. `lookupLiveBinding` must query that live store
atomically and cannot be wired to a cache, a JWT role or an unconditional true
adapter. No database schema or migration was applied for this producer.

   Auth0 logout or refresh-token revocation must not be treated as immediate

5. Publish/provision the independent authorization store/signer only after its
   resources, permissions and operational ownership are separately reviewed.
   No administrator roles are assigned by this setup.
6. Real account login/MFA/issued-token acceptance, cross-client rejection and
   operational revoke/role-change tests remain pending. Sandbox fixtures and

## Continuation implementation

`console-host.mjs` now exposes only reviewed same-origin browser modules and
public configuration, with strict CSP/no-store/no-referrer headers and no
secret/source-directory serving. `console-session.js` attaches the PKCE adapter
to the existing console without customer UI changes. It removes the console's
background-clear hook before starting OAuth so navigation does not erase the
new verifier; a DOM acceptance test covers that transition. Without independent
policy/checkpoint configuration it shows only sign-in and an inactive notice.

`auth0-browser-acceptance.mjs` is a loopback-only local test harness, never a
Render start command. It can validate an issued signature, issuer, audience,
expiry and MFA proof using the production authenticator, but deliberately denies
every live session. It has no database, role enrollment, governance route or
founder activation. Its UI was opened and the anonymous check denied. Real
Auth0 login/MFA acceptance is still pending private identity/factor enrollment.
After saving the callback, the actual PKCE request reached Universal Login for
LEQVOR Governance Console. Password/MFA interaction was handed to the owner.
The first foreground helper/browser tabs were interrupted by a new turn; the
harness was restarted as a hidden persistent process and its login tab marked
for handoff. No token, password or MFA code was read or logged. Do not confuse a
prepared harness with a passed login.
